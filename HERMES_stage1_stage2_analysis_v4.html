Executive Summary & Gap Analysis

SLIDE 01

AI 자율주행 로봇청소기 'HERMES' 프로젝트는 상용 배포 2개월 전 시점에 예산 120% 초과, 일정 2개월 지연, 현장 성공률 58%라는 치명적 붕괴를 맞이했습니다.

제공된 18종의 Data Pack을 교차 검증한 결과, 본 위기는 단순한 기술 스택의 한계가 아니라 가짜 성과(Vanity Metrics) 조작, 변경 통제 실패, 리스크 방치, 현장 데이터 왜곡 등 구조적(Systemic) 원인에서 비롯되었습니다. 글로벌 표준 프레임워크 관점에서 핵심 원인을 분석하고, 향후 이러한 파국을 예방하기 위한 AI Agent 기반의 미래 통제 방안을 제시합니다.

Core Problem 1: 요구사항 변경 통제 실패 (Scope Creep)

SLIDE 03
데이터 디텍팅: `05_change_requests.csv`에서 VLM 클라우드 아키텍처 변경을 수반하는 CR이 PM 승인하에 강행되었고, 직후 `07_ai_infra_cost.csv` 인프라 예산이 폭증한 인과관계를 식별.

근본 원인 (Mindset): Ownership 부재. PM이 본인이 승인한 거대한 스코프 변경의 후속 파급효과(클라우드 과금)를 통제하지 않고 책임 회피.

도메인 매핑: Planning Domain Delivery Domain

AI Use Case (Scope Predictor): CR 등록 시 아키텍처 의존성과 클라우드 API 호출량 변화를 기반으로 향후 인프라 예산 증분을 자동 시뮬레이션하여 승인권자에게 경고 창을 띄움.

Core Problem 2: 가짜 성과 조작 및 지표 왜곡

SLIDE 04
데이터 디텍팅: `06_evm_weekly.csv`는 30주차까지 완벽한 Green이나, `04_jira_issues.csv`를 대조하면 완료된 Task의 평균 난이도(Story Point)가 지속 추락(3.2 → 1.5)하는 눈가림 패턴 발각.

근본 원인 (Mindset): Value-driven 부재. 실질적 프로젝트 완성보다 거버넌스용 성과 지표(SPI) 달성에만 매몰됨.

도메인 매핑: Measurement Domain Stakeholder Domain

AI Use Case (Metrics Auditor): 표면적인 진척률뿐만 아니라 완료된 이슈의 복잡도, 적체된 Core 백로그 비율을 교차 분석하여 Vanity Metric 징후 발견 시 리더십에 Red Flag 통보.

Core Problem 3: 식별된 리스크 방치

SLIDE 05
데이터 디텍팅: `11_risk_register.csv`에 High Impact의 클라우드 비용 리스크(RSK-06)가 5월 20일 등록되었으나, 대응 계획(Mitigation Plan)이 수개월째 '공란'인 점 발견.

근본 원인 (Mindset): Proactive 부재. 리스크를 식별만 하고 후속 대응 조치와 예비비 할당을 하지 않는 치명적 수동성.

도메인 매핑: Risk Domain Project Work Domain

AI Use Case (Risk Tracker): High 등급 리스크 등록 후 72시간 내 대응 계획이 등록되지 않으면, 슬랙/팀즈 봇이 PM 및 스폰서 채널로 지속적인 경고 및 조치 촉구 알림 발송.

Core Problem 4: 현장 데이터 외면과 품질 왜곡

SLIDE 06
데이터 디텍팅: 랩 테스트 성공률(93%)과 현장 실사업장 성공률(58%) 간의 극단적 격차(`10_navigation_eval_vs_field.csv`). 모든 핵심 편익 지표(`02_benefit_register.csv`) 측정 포기 상태.

근본 원인 (Mindset): Value-driven 부재. 고객이 겪는 실제 현장 품질(VLM 할루시네이션, 통신 단절)을 도외시함.

도메인 매핑: Quality Domain Measurement Domain

AI Use Case (Field Insight): 실물 기기 텔레메트리 에러 로그와 CI/CD 커버리지를 실시간 매핑하여, 랩실-현장 간 괴리도 임계치 초과 시 추가 상용 배포 파이프라인 차단.

Core Problem 5: 팀 소통 파괴와 은폐

SLIDE 07
데이터 디텍팅: 41건의 익명 불만이 쏟아진 회고 보드가 스티어링 커미티 의사록(`15_governance_log.csv`)에 전혀 보고되지 않고 6월부터 회고 자체가 증발됨.

근본 원인 (Mindset): Proactive / Ownership 동시 붕괴. 개선을 위한 피드백 루프(Agile Practice)를 끊고 위기를 조직 상부에 은폐함.

도메인 매핑: Team Domain Development Approach Domain

AI Use Case (Voice of Team Analyzer): 익명 게시판 텍스트, 메신저 감성 분석, Jira 야근 커밋 비율 등을 종합 처리하여 프로젝트 조직 건강 지표(Burnout Index)를 자동 생성.
