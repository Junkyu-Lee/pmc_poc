# 핵심 분석 프레임워크 (대회에서 강조하는 차별화 포인트)

## 절대 원칙: 증상이 아닌 근본 원인에 집중

❌ **하지 말아야 할 것:** 프로젝트의 현상/증상을 나열하는 데 그치는 것
- 일정 지연, 재작업, 이해관계자 갈등 = 이것들은 "결과"일 뿐

✅ **해야 할 것:** PMBOK 8판 Mindset 관점에서 근본 원인 도출
- 거버넌스, 범위, 리스크, 이해관계자 관리의 **구조적 문제**를 식별

## 필수 논리 흐름 (4단계)

```
Mindset → Performance Domain → AI Use Case → Future State
```

1. **Mindset** — PMBOK 8판 관점에서 왜 문제가 발생했는지 근본 원인 설명
2. **Performance Domain** — 해당 원인이 어떤 성과 영역과 연결되는지 논리적 매핑
3. **AI Use Case** — 핵심 문제를 해결하기 위한 수단으로서의 AI 활용 방안 제시
4. **Future State** — 개선된 미래 상태 제시

## AI 활용 시 주의사항

- ❌ 단순 자동화 기능 소개 금지
- ✅ 프로젝트의 **핵심 문제를 해결하기 위한 수단**으로 AI를 제시
- AI가 왜 이 문제에 효과적인지, 어떤 구조적 문제를 해소하는지 연결

## 답변 구성 순서

1. 프로젝트 증상 확인 (간단히)
2. **원인 분석** — PMBOK 8판 Mindset 관점에서 WHY 설명
3. Performance Domain 연결
4. AI Use Case로 해결 방안 제시
5. Future State (개선된 상태) 도출

**Why:** 대회에서 차별화되는 핵심 역량은 "증상→원인→해결→미래상태"의 일관된 논리 흐름. 현상 나열만으로는 높은 점수를 받을 수 없음.

**How to apply:** 모든 프로젝트 분석/답변 시 반드시 이 4단계 흐름을 따르고, 특히 "왜 문제가 발생했는가"에 대한 구조적 원인 분석을 가장 두텁게 할 것. [[pm-competition-standard]] [[pm-competition-overview]]
