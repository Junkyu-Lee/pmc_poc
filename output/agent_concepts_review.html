Stage ③ Design — 사전 리뷰

AI Agent 컨셉 설계안

NovaHome Connect 프로젝트의 근본 원인을 해결하기 위한 PM 보조 AI Agent 후보 12종

📌 목적: 팀 리뷰 & 방향성 합의 📊 기준: PMBOK 8판 Mindset → Domain → AI Use Case 🎯 원칙: 증상 치료가 아닌 근본 원인 타격

설계 원칙

왜 이 Agent들인가?

Stage ②에서 도출한 5개 문제의 Root of Roots = #1 거버넌스 부재. AI Agent는 단순 자동화가 아니라, 이 구조적 문제를 해결하여 연쇄적으로 다른 문제도 완화하는 수단으로 설계합니다.

핵심 질문: "이 Agent가 있었다면, NovaHome Connect의 소셜 로그인 사태가 방지되었을까?"
→ Yes라면 근본 원인을 타격하는 Agent. No라면 증상 치료에 불과.

Agent 후보 12종 상세

01

Change Impact AnalyzerPM 역할: 통합 변경 통제 (Integrated Change Control)

#1 거버넌스 Planning
🔔 트리거: 누군가 범위/일정/리소스 변경을 요청하거나 실행할 때
Input
  • 변경 요청 내용
  • 요구사항 목록 + 의존관계 맵
  • 마일스톤/일정 베이스라인
  • 리소스 할당 현황
Output
  • 영향받는 요구사항 리스트 (의존 체인)
  • 일정 영향 시뮬레이션
  • 추가 필요 리소스
  • 리스크 등급 판정
  • 선행 조건 권고
시나리오 예시
Input: "REQ-017 소셜 로그인 베타 포함"
→ Agent 분석 결과:
"REQ-021(보안약관) 미완료로 법적 리스크 HIGH. QA 케이스 +40건으로 G3 Beta 3일 지연 예상. 스폰서 승인 필요. 선행 조건: CRB 완료 + QA 슬롯 확보 + 스폰서 승인"

데모 시나리오 — Agent 연쇄 반응 흐름

"소셜 로그인 투입 사건"이 발생했을 때, Agent가 있었다면?

  PO가 소셜 로그인 투입 요청
          │
          ▼
  ⑤ Meeting Intelligence
  "PO 요청 감지 — PM 이전 합의('비노출')와 충돌"
          │
          ▼
  ① Change Impact Analyzer
  "영향도 HIGH — QA +40건, CRB 미완료, G3 위험"
          │
          ▼
  ④ Dependency Tracker
  "크리티컬 패스 재계산 — G3 3일 지연 예상"
          │
          ▼
  ⑩ Workload & Capacity
  "FE 167% 과부하, QA 3일 초과"
          │
          ▼
  ② Escalation Agent
  "스폰서 + 마케팅실장에 사전 브리핑 필요"
          │
          ▼
  ⑧ Gate Checker
  "G3 통과 확률 35%로 하락"
          │
          ▼
  ⑫ Daily Briefing
  종합 상황 + PM 권장 액션 제시
결론: 개별 Agent가 순차적으로 반응하며, PM에게 완전한 의사결정 컨텍스트를 제공합니다. PM은 "몰랐다"가 아닌 "모든 정보를 바탕으로 결정한다"의 위치에 서게 됩니다.

💬 팀 리뷰 토의 포인트

  3. 데모 방식: 연쇄 반응 시나리오(한 사건 → 여러 Agent 순차 반응) vs 개별 Agent 독립 시연?

  5. 발표 전략: "이 Agent가 있었으면 예방되었을 것" vs "지금이라도 투입하면 해결 가능"?
