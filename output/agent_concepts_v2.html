Stage ③ Design — v2 압축안

PM 종합 판단 AI Agent 설계

12개 개별 리포터 → 4개 종합 판단 Agent로 압축.
각 Agent는 다양한 소스를 스스로 종합하여 PM에게 "판단과 액션"을 제시합니다.

왜 압축하는가?

PM은 "성능 리포트", "리스크 리포트", "이해관계자 리포트"를 각각 받고 싶은 게 아닙니다. PM이 원하는 것은 "지금 내가 뭘 해야 하는지"에 대한 종합 판단입니다.

v1: 12개 개별 리포터
각각의 데이터를 분석해서
각각의 리포트를 생성
→ PM이 직접 종합해야 함
→ "AI 분석 도구 카탈로그"
→
v2: 4개 종합 판단 Agent
여러 소스를 스스로 수집·종합하여
하나의 판단과 권고를 제시
→ PM은 의사결정만 하면 됨
→ "AI PM 코파일럿"
Agent A — 변화 대응

Change Guardian

"이 변경, 받아들여도 되나? 안 되면 어떻게 해야 하나?"

컨셉

프로젝트에 어떤 변화든 감지되면 (범위 변경, 벤더 정책 변경, 일정 변동, 인력 변동 등) 자동으로 다차원 영향을 종합 분석하고, PM에게 "수용/거절/조건부 수용" 판단 근거와 구체적 액션을 제시하는 Agent.

단순히 "영향이 있다"가 아니라 "이 조건이 충족되면 수용 가능, 아니면 대안은 이것"까지 판단합니다.

Input (다양한 소스를 Agent가 직접 종합)

수집하는 정보 소스
변경 트리거범위 변경 요청, 벤더 메일, 정책 변경, 인력 변동, 요구사항 상태 변경
프로젝트 베이스라인요구사항 맵, 의존관계, 마일스톤, 게이트 기준, KPI 목표
리소스 상황팀원별 업무량, 스프린트 가용 용량, 벤더 SLA/리드타임
이해관계자 컨텍스트누구의 관심 영역인지, 기대치, 의사결정 권한 구조
과거 이력유사 변경의 과거 결과, Lessons Learned, 벤더 실제 리드타임
규제/법무 상태CRB 일정, 약관 상태, 보안 검토 진행도

Output (종합 판단)

PM에게 제시하는 결과물
판단 결론수용 / 조건부 수용 / 거절 + 명확한 이유
조건부 수용 시 선행 조건"A, B, C가 충족되면 수용 가능" — 각 조건의 Owner, 소요 기간
거절 시 대안축소 범위, 대체 일정, 다음 스프린트 이동 등 구체 대안
에스컬레이션 필요 여부이 결정이 누구의 승인을 필요로 하는지 + 브리핑 초안
리스크 시나리오수용 시 / 거절 시 각각의 일정·품질·비용 영향 시뮬레이션
영향받는 팀원 알림누가 추가 업무를 받게 되는지, 과부하 경고

시나리오 — "소셜 로그인 투입 사건"

PO(최서린)가 "마케팅 캠페인 때문에 소셜 로그인을 베타에 포함하겠다"고 선언
IN
변경 요청 감지 + 요구사항 맵에서 REQ-017(Deferred) 상태 확인 + REQ-021(보안약관) CRB 미완료 확인 + 현재 QA 용량 산출 + 스폰서 관심영역 매칭 + 과거 유사 변경 이력 검색
⚙
종합 판단 수행: 의존관계 체인 분석 → 일정 영향 시뮬레이션 → 리소스 과부하 계산 → 법무 리스크 평가 → 이해관계자 영향 범위 산정 → 대안 생성
→
판단: 조건부 수용
"현재 상태에서 즉시 수용은 불가. 아래 3개 조건 충족 시 수용 가능:"
① CRB 보안약관 승인 완료 (윤세라, 10/18 예정 — 촉박)
② QA 슬롯 3일 추가 확보 또는 외부 QA 투입 (문해인 확인 필요)
③ 스폰서(이현수 전무) + 마케팅실장 사전 승인 (High-power 관심영역)

대안: 베타 내부 데모만 허용, 정식 론칭(G5)에서 외부 공개
에스컬레이션: 스폰서 브리핑 필요 — 초안 생성됨
경고: 강민재(FE) 167% 과부하 예상, 문해인(QA) +40케이스 수용 불가

Agent B — 상시 감시

Project Pulse

"지금 프로젝트에서 가장 위험한 건 뭐고, 오늘 내가 뭘 해야 하나?"

컨셉

프로젝트의 모든 신호(KPI, 리스크, 일정, 팀 상태, 벤더 상황, 게이트 준비도)를 상시 모니터링하고, 변화가 감지될 때마다 또는 매일 아침 PM에게 "지금 가장 위험한 것 Top 3 + 오늘의 권장 액션"을 종합 판단하여 브리핑하는 Agent.

개별 지표 나열이 아니라 "왜 이것이 지금 가장 위험한지"의 인과 관계까지 설명합니다.

Input (상시 수집 — Agent가 스스로 모니터링)

감시하는 신호 소스
품질/성능 메트릭CI 성공률, p95 응답시간, 오류율, RTM 안정성 — 추세 포함
일정/의존관계마일스톤 진척, 블로커 상태, 크리티컬 패스, 게이트 D-day
리스크 레지스터등록된 리스크 상태 변화 + 미등록 신규 리스크 징후
벤더 상황납기 진행 상태, 커뮤니케이션 빈도/톤, SLA 이탈 징후
팀 상태스프린트 번다운, 액션 아이템 이행률, 과부하 지표
이해관계자 동향미응답 이슈, 기대-현실 갭 변동, 최근 커뮤니케이션 톤

Output (매일 아침 또는 이상 감지 시)

PM 브리핑
프로젝트 건강 상태🟢/🟡/🔴 종합 등급 + 전일 대비 변화 방향
Top 3 위험 요소가장 위험한 3가지 + 왜 위험한지(인과 관계) + 미조치 시 시나리오
오늘의 권장 액션PM이 오늘 해야 할 구체적 행동 3가지 (우선순위 순)
게이트 카운트다운다음 게이트까지 남은 기간 + 현재 통과 확률 + 미충족 항목
조기 경보아직 문제가 아니지만 추세상 문제가 될 예측 (선행 지표)
좋은 소식해소된 리스크, 완료된 마일스톤, 개선된 지표

Agent C — 소통 오케스트레이션

Comm Orchestrator

"이 결정을 누구에게, 어떤 관점으로, 언제 전달해야 하나?"

컨셉

의사결정이 내려지거나 상황 변화가 발생했을 때, 각 이해관계자에게 맞춤형 메시지를 자동 생성하는 Agent. 같은 사안이라도 스폰서에게는 비즈니스 임팩트 관점으로, 기술팀에게는 기술적 영향 관점으로, 마케팅에게는 일정/기능 관점으로 다르게 전달합니다.

또한 "전달하지 않으면 안 되는 사안"을 자동 감지하여 PM이 누락하는 것을 방지합니다.

Input

수집하는 정보 소스
의사결정/변경 내역회의 결정, 범위 변경, 일정 변동, 리스크 등급 변화
이해관계자 프로필역할, 관심영역, 선호 소통방식, 보고 주기, 권한 수준
커뮤니케이션 이력마지막 보고 시점, 미공유 사안 누적, 미응답 건
Agent A/B의 판단 결과에스컬레이션 필요 여부, 리스크 등급 변화

Output

PM에게 제시하는 결과물
필수 전달 대상 + 이유"이 결정은 반드시 A, B에게 전달 필요" + 왜 그런지
이해관계자별 맞춤 메시지 초안같은 사안을 역할별 관점으로 재구성한 메시지
전달 타이밍 권고"결정 후 24시간 내" / "다음 회의 전" / "즉시"

Agent D — 문제 진단

Root Cause Advisor

"증상 말고 진짜 원인이 뭐고, 단기/장기로 뭘 해야 하나?"

컨셉

문제가 발생했을 때 PM이 "왜?"라고 물으면, 프로젝트의 모든 맥락을 종합하여 PMBOK 8판 관점의 근본 원인 진단 + 단기 조치 + 장기 예방안을 일관된 논리 흐름(Mindset → Domain → 해결책)으로 제시하는 Agent.

핵심 차이: Agent 간 연결

A가 "이 변경은 HIGH"라고 판단하면 → C가 자동으로 "스폰서에게 이렇게 브리핑하라" 생성.
B가 "CI 3일 연속 하락"을 감지하면 → D가 자동으로 근본원인 진단 수행.
D가 "구조적 문제 반복"을 경고하면 → A가 향후 유사 변경에 자동으로 더 엄격한 기준 적용.

4개 Agent가 독립적으로 작동하되, 서로의 결과를 Input으로 활용하여 점점 더 정확한 판단을 합니다.

데모 시나리오 — 4 Agent 연쇄 작동

"소셜 로그인 사태"에서 4개 Agent가 순차적으로 어떻게 PM을 보조하는지

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  [시점 1] PO가 소셜 로그인 투입 선언
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  → Agent A (Change Guardian) 작동
    수집: 의존관계 + QA용량 + CRB상태 + 스폰서관심영역 + 과거이력
    판단: "조건부 수용. 선행조건 3개. 즉시 수용 불가."
    ────────────────────────────────────────────────────

  → Agent C (Comm Orchestrator) 자동 연계
    입력: Agent A 판단 결과 (HIGH 등급 + 스폰서 관심영역)
    출력: "스폰서 + 마케팅실장에 즉시 브리핑 필요"
         + 각각 맞춤 메시지 초안 생성
         + "보내지 않으면 20:00 전무 전화 사태 재현" 경고
    ────────────────────────────────────────────────────

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  [시점 2] 다음날 아침 (가정: PM이 Agent A 권고를 무시하고 투입 진행)
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  → Agent B (Project Pulse) 아침 브리핑
    감지: CI 76%로 하락 + 빌드 충돌 + QA 과부하
    브리핑: "🔴 프로젝트 Critical.
            Top 1: 비인가 변경 3건 동시 적용으로 빌드 불안정
            Top 2: Geo-IP 리드타임 마감 임박
            Top 3: 팀 과부하 — FE 167%, QA 초과"
    ────────────────────────────────────────────────────

  → Agent D (Root Cause Advisor) 자동 연계
    입력: Agent B가 감지한 "CI 3일 연속 하락" 패턴
    진단: "증상: CI 하락. 근본원인: CCB 미작동.
          이건 3번째 반복. 개별 대응 X → 구조 개선 필요.
          제안: CR 없는 머지를 기술적으로 차단하는
          Guardrail 도입"
    ────────────────────────────────────────────────────

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  [결론] Agent가 있었다면?
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✅ Agent A가 "선행조건 미충족" 경고 → PO 독단 투입 방지
  ✅ Agent C가 "스폰서 브리핑 필수" 알림 → 전무 격앙 방지
  ✅ Agent B가 선행지표 감지 → 문제 확대 전 조기 대응
  ✅ Agent D가 패턴 경고 → 동일 실수 반복 구조적 차단
