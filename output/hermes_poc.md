## ▪ 핵심 개념 — PM의 인지 파이프라인을 확장

SLIDE 03

PM이 실제로 돌리는 인지 파이프라인 **보다 → 듣다 → 판단하다 → 행동하다**를 그대로 확장한다. **판단의 주체는 여전히 PM.** 에이전트는 관측·판단의 폭을 넓혀줄 뿐이다.

| **ACT** · 실행 | 판단을 실제 조치로 연결 — 티켓·알림 발행 (PM 승인) |

## ▪ 작동 방식 — 7개 도메인 에이전트가 '합체'

SLIDE 04

각 에이전트는 자기 도메인의 **전문가 역할**을 한다. 사안에 따라 **관련 에이전트들이 함께 활성화·조합**되어, 통합 엔진 **Signal Forge**가 하나의 판단으로 합친다.

| 에이전트 | 도메인 | 책임 (역할·책임) |
| --- | --- | --- |
| **Governance Watchdog** | 거버넌스 | 변경통제·CCB·보고 무결성 위반 감지, 절차 복원 유도 |
| **Change Guardian** | 범위 | Scope Creep·베이스라인 이탈 감지, 변경요청(CR) 필요성 판단 |
| **Schedule Sentinel** | 일정 | 임계경로·게이트 리스크, 지연 파급 분석 |
| **Risk Oracle** | 리스크 | 잠재 위협 식별·평가, 대응 전략 제안 |
| **Stakeholder Pulse** | 이해관계자 | 이해관계자 신뢰·기대 충돌, 소통 필요성 감지 |
| **Resource Radar** | 자원 | 가용 역량·과부하·의존성 병목 감지 |
| **Cost Protector** | 재무 | 예산 초과·예비비 소진·원가 리스크 감시 |

각 에이전트는 이상징후(신호)를 **근거와 함께 감지·제시**하고, 리스크·이슈·CR 분류도 제안한다. **최종 판단과 처리는 PM**이 결정한다.

## ▪ 상충을 '가치'로 결단 — Signal Forge + North Star

SLIDE 05

감지·제시에 그치지 않는다. 대응안이 서로 **상충**하면 **Signal Forge**가 **Mindset·6원칙으로 사고**해 **프로젝트 가치서열(North Star)로 최종 결단**한다.

① 6원칙 기준 검토 → ② 프로젝트의 North Star(가치서열)로 최종 결단


하나의 통합 최적안 도출 + 하위가치 보완책 마련 (실행 전 PM 승인)

판단 기준 — Mindset 3 차원 · 6 원칙

| 선제적 (Proactive) | 소유권 (Ownership) | 가치 중심 (Value-Driven) |
| --- | --- | --- |
| 전체론적 관점 채택 | 책임감 있는 리더 되기 | 가치에 대한 집중 |
| 프로세스·인도물에 품질 내재화 | 권한이 강화된 문화 구축 | 모든 영역에 지속가능성 통합 |

* **North Star = 프로젝트 핵심 가치서열** — 상충의 최종 심판 기준. 특정 도메인에 치우치지 않고, 가치 우선순위에 따라 결단한다.
* **PM 주인의식 유지** — 에이전트는 근거·초안을 제공, 티켓 발행·오너 배정·에스컬레이션의 최종 실행은 PM.

## ▪ PM 워크스페이스 구성 — 기능과 역할

SLIDE 06

PM이 실제로 사용하는 하나의 워크스페이스. 관측(SEE·HEAR) → 판단(THINK) → 실행(ACT)이 아래 기능으로 이어진다.

| 기능 (화면) | 단계 | 역할 |
| --- | --- | --- |
| **홈 대시보드** | SEE | 7개 에이전트 감지 종합 브리핑 · 건강도 · 우선 조치 |
| **PM Note** | HEAR | 메일·전화·메모·회의 등 비정형 신호 입력 |
| **일정** | SEE | 마일스톤·게이트·스프린트 진행 현황 |
| **이슈 & 리스크** | THINK·ACT | 감지 신호 등재 · AI 대응안 생성 · 실제 Jira 티켓 발행 |
| **예산 & 자원** | SEE | 예산 집행·예비비·자원 배분 모니터링 |
| **커뮤니케이션** | ACT | 이해관계자 소통 · 알림/메일 초안 |
| **리포트** | ACT | 주간·스프린트 리포트 자동 생성 |
| **PM 문서** | SEE | 요구사항·TRM·CR·이슈·리스크 단일 원본(SSOT) — 대시보드와 미러링 |

## ▪ 도입 전후 · 확장 · 지속가능성

SLIDE 08

* **Before → After**: 사후 발견·따로 판단·독단 → 상시 스캔·가치 기반 일관 결단·변경통제 자동 유도
* **확장(일반화)**: **과제 정의(문서) 하나**만 교체하면 컨텍스트·분석이 자동 재구성. 다른 과제로 교체 실증 완료.
* **현업 이관**: 사내 LLM + 경량 서버, 기존 Jira/Confluence 재사용. 파일럿 4~6주. 실행은 PM 승인 게이트.
* **지속가능성·운영**: 주기 스캔 + 온디맨드 심의, 산출물 누적. 호출·캐시로 비용 통제. 모든 실행 승인·기록.

예시(NovaHome)·수치(BEN/KPI)는 **본선 당일 실제 과제 baseline**으로 교체. 디자인/슬라이드 포맷은 팀원이 통일.
